## 正式驗收矩陣（尚未執行）

| 裝置     | 同站情境                 | 跨站情境               | 驗收項目                                 |
| -------- | ------------------------ | ---------------------- | ---------------------------------------- |
| 1        | 單站                     | 三站依序切換           | 首載、500 客戶、超過 1000 品項分頁、匯出 |
| 8        | 8 個獨立 session 同站    | 3 打勾、3 報表、2 報價 | 變更接收數、延遲 p50/p95、8 小時穩定度   |
| 10       | 10 個獨立 session 同站   | 4 打勾、3 報表、3 報價 | 同上，另記 peak connections              |
| 8/10 × 3 | 每台同開三站（最壞情境） | 最多 24／30 個分頁     | 對比 8／10 連線情境，不混為一談          |

每個情境執行：

1. 初始訂閱期間另一台新增、更新、刪除；確認游標補差沒有遺漏。
2. 離線兩分鐘再回線、Realtime 中斷但 API 可用、背景 5 分鐘後可見、重整與登入 session 到期。
3. 同一筆同時修改：只能一個 revision 成功，另一個保留草稿並提示衝突。
4. 斷線後重送相同 request_id：只產生一個版本與事件；無法確認回應時先查資料，不改新 request_id 盲重送。
5. 變更發生在交易提交順序邊界；寫入 RPC 全部取得同一 advisory xact lock 後才配序號，交易結束才釋放，確保 watermark 不能越過未提交事件。
6. 從近 30 天歷史做多頁游標查詢，驗證沒有用 timestamp＋offset 導致漏列。報表日列表 50 筆分頁；按需匯出才取得當日所有頁。
7. 上傳 UTF-8 CSV、多組並排、隱藏列、空價、括號負數、單位衝突、前導零、未知品項、取消存檔、磁碟錯誤。Excel 金額及欄寬逐格對照真實範本。
8. RLS：未登入、無成員、停用、viewer、staff、admin；任意直接表寫入、刪除全部、RPC 輸入越權。

## 增量與傳輸

僅 `cs_change_log` 加入 publication；事件包含 seq、kind、id、revision、deleted、day。API 只按需讀一筆或分頁明細。首頁不下載報價 item、對照表或歷史全表。頁面每 30 秒只查 watermark，只有游標落後時補事件；每頁面一個 channel，隱藏時解除。

交易全域 advisory lock 是正確性優先的取捨，8–10 台日常作業需壓測寫入延遲；後續若有高頻寫入需分區游標協議，不可直接移除鎖仍宣稱 sequence 保證提交順序。

目前不自動清理 change_log / request log：清理會使離線游標的補差保證失效。正式用量接近 DB 上限前需設計有低水位與強制重新快照的 retention／歸檔工作，不能直接刪舊事件。這是長期維運待補項目。

## 月流量試算（不是實測）

假設 26 天、8 小時／天、每客戶每天 1 次叫貨、500 客戶、事件下行每接收者 250 bytes、按事件讀取資料 800 bytes；500 次其他業務／天、每筆回應 1500 bytes。這些大小只是可修改假設，未含完整協議成本。

- 8 連線：叫貨 `500×26×8×(250+800)` = 0.1092 GB。
- 其他業務 `500×26×8×(250+1500)` = 0.182 GB。
- 30 秒 watermark：`8×26×8×3600/30×100` = 0.019968 GB（100 bytes 僅為假設的回應體）。
- 首載、Auth、TLS／HTTP header、WebSocket 心跳、重連、Excel 明細與其他背景流量另外測量；不能把前三項加總當作整月真實流量。
- 10 連線約為上述項目 ×1.25；30 分頁則 ×3.75，但後台分頁解除訂閱可減少實際值。

以 `10^9 bytes = 1 GB`，每月一般 Egress ≈ API response bytes×請求次數 + Realtime 下行 bytes×接收連線數 + 心跳／Auth／重連／協議／其他下行。不同事件讀取不同大小，不應一律使用 800 bytes。

預算：打勾單 0.9 GB、異常交接 0.7 GB、報價 0.9 GB、共用 0.5 GB；3 GB 提醒、4 GB 警戒。網站目前展示本頁 API 回應量，不會自動讀取 Supabase Dashboard Usage，也尚未實作 Dashboard 用量門檻自動關閉背景預載。500 MB DB、200 萬訊息、200 連線與 5 GB 一般 Egress 均需核對帳戶當期方案；cached egress 不能挪為一般 egress。

實測請匯出瀏覽器 Network HAR（先清除授權資訊）與 WS frame 大小，記錄各操作頻率、事件接收者、查詢次數，與 Supabase Dashboard Usage 以相同期間對帳。長時間測試記錄最大記憶體、重連次數、失敗率、同步 p95；不可只記 API 200。
